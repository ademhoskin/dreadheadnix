# Toolchain

Every tool here comes from nixpkgs — nothing is vendored. They are declared in
`home-manager/home.nix` (either in `home.packages` or as a `programs.*` module),
so this page is an index into that file rather than a second source of truth.

The point of the "wired in" lines is to know what breaks if you remove
something. Several tools are referenced by config elsewhere in this repo, and a
few are installed but do nothing on their own.

## Shell

| Tool | Use | Wired in |
| --- | --- | --- |
| **zsh** | The shell | `programs.zsh` — everything below is hooked up through it |
| **powerlevel10k** | Prompt | `programs.zsh.initContent` sources it, then `~/.p10k.zsh` |
| **fzf** | Fuzzy finder | `programs.fzf.enableZshIntegration`; also used by `frg` and by zsh-fzf-tab |
| **zoxide** | `cd` that learns | `programs.zoxide.enableZshIntegration`; `zii` alias |
| **zsh-fzf-tab** | fzf-driven tab completion | Sourced from `initContent` |

### Things that are easy to miss

**The prompt is overridden twice.** `~/.p10k.zsh` (generated by `p10k configure`)
sets the base style, then `initContent` overrides several colours with red hex
values afterwards. Editing `.p10k.zsh` alone will not change those.

**`frg` is the one custom function** — ripgrep, fzf, bat and `$EDITOR` glued
together:

```sh
frg <pattern>          # search, preview with bat, open the hit in $EDITOR
```

**Custom key bindings:** `Ctrl-P`/`Ctrl-N` for history-search, `Ctrl-F` to
accept an autosuggestion.

**`DREADHEADNIX` points at this repo.** It defaults to `/etc/dreadheadnix`,
where the ISO bakes it in on the installed system; export it yourself for a
development checkout.

```sh
cfg         # page nixos/configuration.nix
cfgh        # page home-manager/home.nix
cfgt        # page this file
cfgcheck    # build the config without switching to it
```

`cfgcheck` is the one worth knowing: `nixos-rebuild build` builds the whole
system and writes a `result` symlink, so a bad option name or broken import
fails immediately rather than at the next rebuild. It does not need root. To
then switch for real, `sudo nixos-rebuild switch --flake "$DREADHEADNIX#inspiron"`.

These compose with `bs` — `cfg`, then `bs` on a section of the file.

**`EDITOR` is `nvim`, not Emacs.** `Claude Code`, `git commit` and `frg` all use
it. If you switch fully to Doom and want `emacsclient` instead, that is the
variable to change.

## Search and files

| Tool | Use | Wired in |
| --- | --- | --- |
| **ripgrep** (`rg`) | Fast recursive grep | `frg`; Doom's search |
| **fd** | Friendlier `find` | Nothing — standalone |
| **bat** | `cat` with syntax highlighting | `cat`/`catp` aliases, `bs`, the fzf preview in `frg` |
| **eza** | Modern `ls` | `ls`, `ll`, `la`, `tree` aliases replace the originals |
| **glow** | Markdown renderer in the terminal | Nothing — standalone |
| **bottom** (`btm`) | `top` replacement | The `top` alias |

Note the aliases are *replacements*: `ls` runs `eza`, and `tree` is
`eza --tree`. The real binaries are still there if you need them.

### Reading files with bat

Two aliases, because the useful behaviour differs by intent:

```sh
cat file        # bat --style=plain --paging=never — looks like cat, but coloured
catp file       # paged and fully decorated; use this to actually read something
```

`cat` is safe to keep aliased: bat drops colour on its own when stdout is not a
terminal, so `cat f | grep x` behaves as expected.

**Jumping to a section.** `bs` opens a file at the first heading matching a
string and highlights that line:

```sh
bs docs/toolchain.md Languages
bs README.md Install
```

It works by grepping for heading lines, then narrowing to a fixed-string match —
so the search term is not treated as a regex.

Worth knowing: **bat has no `+N` convention.** `bat +3 file` tries to open a
file literally named `+3` and fails with "No such file or directory". The line
range is what starts output at a line:

```sh
bat -r 40: file            # start at line 40
bat -r 40:60 file          # lines 40 to 60
bat -H 40 -r 40: file      # start at 40, with 40 highlighted
```

`-H` (`--highlight-line`) accepts the same `N:M` ranges as `-r`.

## Git

| Tool | Use | Wired in |
| --- | --- | --- |
| **git** | VCS | `programs.git.settings` |
| **delta** | Syntax-highlighted diffs | `core.pager`, `interactive.diffFilter` |
| **lazygit** | TUI for git | Nothing — run `lazygit` yourself |
| **gh** | GitHub CLI | Nothing; also how CI pushes here |

`delta` is worth calling out: it was installed for a long time without ever being
referenced, which meant it did nothing at all. The three settings that make it
work are the pager, the `diffFilter` (this is what colours `git add -p`), and
`delta.navigate`.

`pull.rebase = true` is set globally, so `git pull` rebases rather than merges.

| Tool | Use | Wired in |
| --- | --- | --- |
| **tmux** | Terminal multiplexer | `dotfiles/tmux/tmux.conf`, plugins via tpm |
| **alacritty** | Terminal | `dotfiles/alacritty/alacritty.toml` |

## Editors

| Tool | Use | Wired in |
| --- | --- | --- |
| **Doom Emacs** | The default editor | `dotfiles/doom/` — `init.el`, `config.el`, `packages.el` |
| **Neovim** + LazyVim | Secondary editor | `dotfiles/nvim/` |

Doom is cloned at activation because `doom sync` writes into `~/.config/emacs`;
only the three config files are symlinked. **After editing `init.el` or
`packages.el`, run `~/.config/emacs/bin/doom sync`.**

Doom skips a module it cannot resolve with no error and no warning — a typo
costs you the feature silently.

LazyVim's `lazyvim.json` and `lazy-lock.json` are seeded as writable copies
rather than symlinks, because LazyVim rewrites both at runtime and a store
symlink is read-only.

**Neovim has an AI assistant Doom does not.** `avante.nvim` is configured for
DeepSeek in `dotfiles/nvim/lua/plugins/avante.lua`. There is no equivalent in
the Doom config.

## Languages

Each entry is the compiler, the language server and the formatter. The LSPs are
consumed by whichever editor you use.

| Language | Compiler / runtime | LSP | Formatter |
| --- | --- | --- | --- |
| C / C++ | `clang`, `lld` | `clang-tools` (clangd) | `clang-format` |
| Rust | `cargo`, `rustc` | `rust-analyzer` | `rustfmt` |
| Go | `go` | `gopls` | `gofumpt`, `gotools` |
| Zig | `zig` | — | `zig fmt` |
| Java | `jdk21` | — | — |
| .NET | `dotnet-sdk` | — | — |
| Node / JS / TS | `nodejs`, `bun`, `pnpm`, `yarn` | **none** — see below | `prettier` |
| YAML | — | `yaml-language-server` | — |
| Python | `python3`, `uv`, `pipx` | — | `black`, `isort` |
| OCaml | `ocaml`, `opam`, `dune_3` | — | — |
| Nix | — | `nil` | `nixfmt` |
| Lua | — | — | `stylua` |
| Shell | — | — | `shfmt`, `shellcheck` |
| Build systems | `gnumake`, `cmake`, `ninja`, `pkg-config` | — | — |
| Debugging | `gdb`, `valgrind`, `delve`, `lldb` | — | — |

Notes:

- **There is no JavaScript/TypeScript language server installed.** Doom asks for
  one — `(javascript +lsp)` and `(web +lsp)` — and LazyVim's `lang.typescript`
  extra does too, but neither `typescript-language-server` nor `vtsls` is in
  `home.packages`. Doom would find nothing on `PATH`; LazyVim may paper over it
  by installing one through Mason into `~/.local/share/nvim`, which works
  because `nix-ld` is enabled, but that is not managed by this repo and will not
  survive a cleared nvim data dir. Adding one to `home.packages` is the fix.
- **`nodejs` provides `npm`** — there is no separate `npm` package.
- **`gotools` is what provides the `goimports` binary.** The attribute `goimports`
  does not exist.
- **`python3Packages.debugpy`**, not `debugpy`.
- `rustup` is *not* used; the Rust toolchain comes from nixpkgs, so
  `rustup toolchain install` will not behave as expected.

## AI

| Tool | Use | Wired in |
| --- | --- | --- |
| **claude-code** | Claude Code | `~/.claude/CLAUDE.md` + `settings.json` from `claude/` |

The credential is **not** in the repo. It is read at shell start from
`~/.config/claude/env`, which is outside the tree:

```sh
install -Dm600 /dev/null ~/.config/claude/env
printf 'export ANTHROPIC_AUTH_TOKEN=%s\n' '<token>' > ~/.config/claude/env
```

The variable is `ANTHROPIC_AUTH_TOKEN`, not `ANTHROPIC_API_KEY` — DeepSeek's
endpoint takes the former, and getting it wrong produces an auth failure that
looks like a bad key.

`ANTHROPIC_BASE_URL` and the model names are in `home.sessionVariables`. The
models carry a `[1m]` suffix for the 1M-context variant; dropping it silently
selects the smaller model.

## Adding or removing a tool

Add it to `home.packages` in `home-manager/home.nix`. If a `programs.<name>`
module exists, prefer it — it also creates the config file, which hand-writing
a dotfile would duplicate.

Before removing anything, check the "wired in" line above. The ones that break
something silently are `ripgrep` and `bat` (used by `frg`), `fzf` and `zoxide`
(hooked into zsh), and anything a `programs.*` module manages.

Verify an attribute exists before adding it — several plausible names are not
packages in nixpkgs 26.05, including `git-delta`, `goimports`, `debugpy`,
`codelldb`, `tmuxPlugins.tpm`, and `nodePackages.*`. This is the class of error
CI's eval step catches, because there is no Nix on the development machine.
